این تحویل بخش مشتری را در پروژه Vue فعلی پیاده می‌کند. مبنا commit زیر است:
`88c82161631635ff8f28d8c74601e610867d3857`
روی سرور، دامنه اصلی یا GitHub اعمال نشده است.

## نصب

ابتدا آخرین بسته بک‌اند `bazbia-coins-backend.zip` و migrationهای آن باید نصب شوند.
سکه‌ها و نسخه‌های پک را پس از ثبت تصاویر لازم، is_published=True کنید.

۱. فایل‌های پوشه src داخل بسته را در مخزن bazbia-vue ادغام کنید.
۲. چهار فایل موجود تغییر کرده‌اند: router، Header، payment.types و PaymentVerifyView؛ اگر بعد از commit مبنا تغییر کرده‌اند، از integration.patch برای ادغام استفاده کنید.
۳. آدرس API در تنظیم فعلی `VITE_API_URL` باقی می‌ماند. مقدار پیش‌فرض:

```env
VITE_API_URL=https://backend.bazbia.ir/api
```

متغیر VITE در زمان build خوانده می‌شود. اگر backend یا مسیر API را عوض کردید، دوباره build بگیرید.
پکیج تازه‌ای به package.json اضافه نشده است.

```bash
npm ci
npm run build
```

فرمان build قبلی پروژه، پس از Vite اسکریپت prerender-products را اجرا می‌کند؛ آن مرحله به دسترسی API و sitemap فعلی محصولات نیاز دارد.
رفتار آن اسکریپت تغییر نکرده و برای سکه‌ها prerender تازه اضافه نشده است.
در این محیط `npm run build:spa` موفق اجرا شد؛ مرحله شبکه‌ای prerender محصولات اجرا نشده است.

بعد از build معمول خودتان، محتوای dist را طبق روش فعلی روی هاست فرانت قرار دهید.
بسته تحویلی source و patch است؛ dist/node_modules یا داده آزمایشی در آن نیست تا خروجی SEO قبلی با یک build ناقص جایگزین نشود.
مسیرهای جدید نیز باید با rewrite فعلی SPA به index.html باز شوند؛ مستقیم‌رفتن به آدرس و Refresh را روی هاست بررسی کنید.

## مسیرهای فرانت

| مسیر | کاربرد |
|---|---|
| `/coins` | سکه‌های تکی، جست‌وجو و فیلتر |
| `/coin-packs` | پک‌های سکه |
| `/coins/:slug` | نوع سکه، سال/گونه و نمونه قابل خرید |
| `/coin-packs/:slug` | نسخه پک، عکس و محتویات |
| `/coins/year/:calendar/:year` | انتقال به فهرست فیلترشده همان سال و تقویم |

مثال:

```text
/coins?issuer=iran&calendar=solar_hijri&year=1373&in_stock=true
/coin-packs?calendar=solar_hijri&year=1373
/coins/250-rial?issue=12&variant=43
```

issue شناسه CoinIssue و variant شناسه ProductVariant است.
گزینه انتخاب‌شده با query ذخیره می‌شود؛ Refresh، لینک مستقیم و بازگشت مرورگر به همان انتخاب برمی‌گردند.
اگر نمونه لینک دیگر منتشر نباشد، پیام بررسی انتخاب نمایش داده می‌شود و نمونه موجود دیگری ممکن است نمایش داده شود.

- حالت بارگذاری، نتیجه خالی، خطای API و تلاش مجدد؛
- لغو درخواست‌های قبلی هنگام جابه‌جایی برای جلوگیری از نمایش پاسخ کهنه؛
- عکس رو/پشت/لبه و جزئیات، نمای بزرگ و عنوان جزء پک در تصاویر؛

- توضیح صریح عکس اختصاصی یا عکس نمونه برای موارد مشابه؛

- شناسنامه، ترکیب فلزی هر بخش، عیار، ضرابخانه، نوشته‌ها و مراجع؛

- منوی سکه و کلکسیون در هدر دسکتاپ و منوی موبایل؛
- نمایش پیام بررسی پرداخت پس از لغو سفارش وقتی requires_review=True باشد؛ در این حالت پیام «سفارش تأیید شد» نمایش داده نمی‌شود.

## اتصال API

سرویس `coin.service.ts` همان baseURL تنظیم‌شده کلاینت فعلی را استفاده می‌کند.
برای GETهای عمومی از کلاینت مجزا استفاده شده تا `_t` و `session_key` تزریق نشوند؛ endpointهای سکه این پارامترهای ناشناخته را رد می‌کنند.
این درخواست‌های عمومی به توکن یا کوکی نیاز ندارند. سبد خرید همچنان با cartStore و session/JWT فعلی کار می‌کند.

| فرانت | endpoint بک‌اند |
|---|---|
| فهرست سکه | `GET /api/coins/` |
| جزئیات سکه | `GET /api/coins/<slug>/` |
| فهرست پک | `GET /api/coins/packs/` |
| جزئیات پک | `GET /api/coins/packs/<slug>/` |
| فیلترها | `GET /api/coins/filters/` |
| خرید | `POST /api/orders/cart/add/` با variant_id و quantity |

قیمت به بک‌اند ارسال نمی‌شود. کارت، قیمت از کمترین نمونه متناظر را نشان می‌دهد؛ انتخاب نهایی در جزئیات است.
شناسه CoinType یا CoinSpecimen به جای variant_id در خرید استفاده نمی‌شود.
عدم موجودی در فرانت دکمه خرید را غیرفعال می‌کند؛ تصمیم نهایی موجودی با بک‌اند است.
لینک خارجی تصاویر، گواهی و مرجع فقط با پروتکل http/https نمایش داده می‌شود؛ متن توضیحات با HTML خام render نمی‌شود.

## بررسی انجام‌شده

- build SPA با Vite موفق؛
- آزمون مرورگر Chromium با خود API محلی آخرین بک‌اند و SQLite آزمایشی؛
- مشاهده فهرست و جزئیات، فیلتر سال با ارقام فارسی و لینک مستقیم نمونه؛
- خرید مهمان سکه و پک؛ بررسی variant_idهای ارسالی و پاسخ واقعی سبد؛
- نمونه ناموجود، غیرفعال بودن خرید و باقی‌ماندن انتخاب پس از Reload؛
- جدول اجزای پک و نمایش نسخه انتخابی؛
- موبایل ۳۹۰ پیکسلی، بازشدن فیلترها و نبود overflow افقی در کل صفحه؛
- نبود خطای JavaScript صفحه در مسیرهای بررسی‌شده؛
- بررسی تصویری دسکتاپ و موبایل با داده و تصویر صریحاً آزمایشی، بدون نوشتن روی API تولید.

`vue-tsc` کل مخزن ۷۰ خطای از قبل موجود دارد. همان بررسی روی commit اصلی نیز ۷۰ خطا با همان مشخصات داد؛
هیچ خطای جدیدی به آن‌ها اضافه نشده و در فایل‌های جدید سکه خطایی گزارش نشد.
این تحویل خطاهای قبلی بخش‌های دیگر پروژه را اصلاح نکرده است.

## محدوده

این بخش برای مشتری است؛ فرم مدیریتی Vue برای آماده‌سازی پک و انتشار اضافه نشده و مدیریت از ادمین و API staff بک‌اند انجام می‌شود.
SSR، prerender اختصاصی سکه، sitemap سکه‌ها و داده ساختاریافته SEO مرحله جدا هستند.
برای تطبیق نهایی با دامنه، CORS، تصاویر واقعی و درگاه واقعی، بعد از نصب بک‌اند و build روی هاست آزمون کنید.
