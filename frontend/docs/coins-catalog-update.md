# کاتالوگ مستقل سکه‌ها

این به‌روزرسانی روی نسخه قبلی بخش سکه بازبیا نصب می‌شود. بسته شامل پوشه backend و frontend است؛ محتوای هر پوشه را در ریشه پروژه مربوط جایگزین کنید. به تنظیمات، مسیرهای اصلی پروژه و مدل محصولات عادی تغییری اضافه نشده است.

## نصب

ابتدا از دیتابیس و فایل‌های پروژه نسخه پشتیبان بگیرید. فایل‌های backend را جایگزین کنید و در محیط مجازی بک‌اند اجرا کنید:

```sh
python manage.py check
python manage.py migrate
```

مهاجرت جدید coins/0003 لازم است. این مهاجرت نوع سکه‌هایی را که قبلاً نمونه فروش منتشرشده داشتند منتشر نگه می‌دارد؛ بقیه پیش‌نویس هستند. هیچ موجودی یا قیمت یا سفارشی تغییر نمی‌کند. تصاویر فروشی به تصاویر مرجع تبدیل نمی‌شوند؛ تصاویر مرجع را جدا ثبت کنید.

سپس فایل‌های frontend را جایگزین کنید:

```sh
npm ci
npm run build:spa
```

این دستور فقط SPA را می‌سازد؛ اگر انتشار شما شامل صفحات ازپیش‌ساخته SEO است، روند build فعلی خودتان را هم حفظ کنید. بک‌اند باید پیش از فرانت به‌روزرسانی شود.

## ثبت سکه بدون فروش

در ادمین «انواع سکه»، معرفی کوتاه، توضیحات قبلی، داستان، منابع داستان و «انتشار در کاتالوگ» مستقل از نمونه فروش است. ساخت Product یا ProductVariant برای ثبت کاتالوگی لازم نیست. نوبت‌های ضرب زیر همان سکه در صفحه عمومی نمایش داده می‌شوند؛ در این نسخه تمام نوبت‌های ثبت‌شده یک نوع سکه منتشرشده عمومی هستند. یادداشت داخلی notes نوبت ضرب عمومی نمی‌شود؛ برای داستان از فیلد description جدید استفاده کنید.

«تصاویر مرجع کاتالوگ» از ادمین جداگانه یا inline نوع سکه قابل ثبت است: فایل یا URL، نما، عنوان، منبع تصویر، ترتیب و نوبت ضرب اختیاری. نوبت انتخاب‌شده باید متعلق به همان نوع سکه باشد. تصاویر مرجع مستقل از عکس واقعی کالای فروشی هستند. سکه بدون عکس با جایگزین تصویری نمایش داده می‌شود.

داستان متن ساده و امن است. پاراگراف‌ها را با خط خالی جدا کنید، تیتر را با `## ` و آیتم‌های فهرست را با `- ` در ابتدای خط بنویسید. HTML اجرا نمی‌شود. منابع داستان متن ساده است. توضیح داستان برای هر نوبت ضرب جداگانه نیز در دسترس است.

## API و نمایش

آدرس‌ها ثابت‌اند: /api/coins/ و /api/coins/<slug>/ اکنون تمام انواع منتشرشده در کاتالوگ را برمی‌گردانند، حتی بدون محصول یا نمونه فروش. جزئیات فیلدهای introduction، story، story_sources، images و برای هر نوبت description و images دارد. تصویر کارت از تصاویر مرجع است. قیمت ممکن است null باشد. ترتیب پیش‌فرض کاتالوگ نام است؛ در مرتب‌سازی قیمت، موارد بدون قیمت انتهای فهرست می‌آیند.

فیلتر موجودی، کیفیت و قیمت همچنان برای یافتن عرضه‌ها در دسترس است؛ سکه فاقد عرضه در فیلتر «بدون نمونه موجود» دیده می‌شود. فیلترهای کشور، جنس، سال و سایر اطلاعات کاتالوگی به وجود محصول وابسته نیستند. API پک‌ها طبق نسخه قبلی فروش‌محور باقی مانده است.

نمونه فروش تنها با قواعد انتشار، قیمت مثبت، محصول فعال و تصاویر لازم عرضه می‌شود. افزودن به سبد همچنان variant_id واقعی نمونه است؛ عکس مرجع و داستان جایگزین شرح کیفیت نمونه فروشی نمی‌شوند.

فرانت در بخش سکه بنر و راهنمای مستقل، کارت‌های کاتالوگی، داستان، تصاویر مرجع، جدول سال‌ها و دکمه خرید کنار نوبت موجود دارد. رنگ سبز هدر فعلی بازبیا حفظ شده و CSS به .coin-page محدود است.

## اعتبارسنجی

۱۰۵ تست بک‌اند از جمله آزمون‌های قبلی سفارش، پرداخت و محصولات عادی و آزمون‌های کاتالوگ مستقل پاس شدند. build:spa موفق است. بررسی نوع کل پروژه همچنان خطاهای قبلی بخش‌های دیگر دارد؛ در فایل‌های بخش سکه خطایی گزارش نشد. تست روی MySQL و درگاه واقعی اجرا نشده است. این بسته روی سرور منتشر نشده است.

بررسی مرورگر نیز با API واقعی محلی انجام شد: کاتالوگ بدون فروش، داستان و تصاویر مرجع، افزودن variant صحیح به سبد، نمایش در عرض ۳۹۰ پیکسل بدون سرریز افقی و نبود خطای JavaScript تأیید شد.
